# 《리듬 구조대》 다음 단계 설계서

작성일: 2026-08-13
기준 브랜치: `main` MVP
대상: 초등 5~6학년 중심의 1인 브라우저 플레이어

## 1. 목적과 범위

현재 MVP는 본부에서 임무를 선택하고 하나의 패턴을 입력한 뒤 결과를 받는 짧은 수직 슬라이스다. 다음 단계는 이 흐름을 3~15분 동안 반복할 수 있는 임무로 확장하고, 입력의 손맛과 성장 보상을 강화한다.

승인된 다음 작업은 다음 네 축으로 나눈다.

1. **임무 진행 심화**: 임무 하나에 여러 수리 지점을 넣고 지점마다 새 패턴, 복구, 콤보, 보상을 연결한다.
2. **피드백과 오디오**: 성공·실수·복구·완료를 시각·진동·짧은 소리로 구분한다. 소리를 끈 상태에서도 의미가 유지된다.
3. **꾸미기와 기지 성장**: 고정 조건으로 캐릭터 스킨, 신호 테마, 기지 장식을 해금한다. 무작위 상자와 유료 보상은 사용하지 않는다.
4. **모바일과 플레이테스트**: 좁은 화면의 터치 조작을 보장하고, 키보드·마우스·터치·접근성 설정을 반복 검증한다.

이번 구현 사이클은 1~3번을 완료했다. 4번의 기본 좁은 화면·키보드·축소 모션 검증도 포함했으며, 기기별 확장 플레이테스트는 후속 작업으로 남긴다.

### 구현 상태

- **완료**: 임무 다중 수리 지점 루프, 임무 전체 통계 집계, 마지막 지점의 단일 보상, 성공·실수·회복·완료 피드백, 소리·진동 설정 연동, 좁은 화면 HUD 보정
- **완료**: 고정 조건의 스킨·기지 장식 해금·선택 저장, 날짜별 업데이트 내역 패널, 본부 반응형·키보드·축소 모션 검증
- **후속 작업**: 실제 모바일 기기별 확장 플레이테스트 매트릭스와 장시간 사용성 확인

이번 사이클에서 구현한 범위는 `MissionRunState`와 기존 `MissionState`의 조합으로 제한한다. 임무 중 새로고침 시 미완료 보상을 저장하지 않는 정책과 기존 `Progress` 저장 형식은 유지한다.

## 2. 다중 수리 지점 플레이 루프

임무는 `repairPoints`개의 수리 지점을 순서대로 진행한다.

```text
임무 선택
→ 지점 패턴 미리보기
→ 네 방향 입력
→ 지점 판정·콤보 갱신
→ 다음 지점 패턴 생성
→ 모든 지점 완료
→ 임무 전체 보상·결과
```

기존 `MissionState`는 한 패턴의 커서와 실수를 담당하는 단위로 유지한다. 새 `MissionRunState`가 여러 지점의 순서, 완료 수, 현재 지점, 임무 전체 실수, 최고 콤보, 사용한 복구 수를 조합한다. 지점 완료마다 다음 지점으로 넘어가며, 마지막 지점에서만 `ResultScene`으로 이동한다.

임무 설정의 고정 값은 다음과 같다.

| 임무 | 수리 지점 | 패턴 길이 | 장애물 |
| --- | ---: | ---: | --- |
| `short-01` | 3 | 3~6 | 없음 |
| `medium-01` | 5 | 5~9 | 드론 |
| `long-01` | 7 | 7~11 | 드론+가림 순차 |

패턴은 `PatternGenerator`를 통해 생성하고 테스트에서는 주입한 난수로 결정 가능하게 한다. 튜토리얼만 첫 패턴을 `['up']`으로 고정해 첫 경험과 E2E 안정성을 유지한다. 이후 튜토리얼 지점은 짧은 고정 패턴으로 이어진다.

## 3. 판정·복구·보상

- 각 지점의 정확 입력은 현재 콤보를 증가시킨다.
- 오입력은 지점 커서를 처음으로 되돌리고 실수를 1회 증가시킨다.
- 임무 전체에서 복구는 최대 2회이며, 복구 사용 시 현재 지점 패턴을 다시 미리 보여 준다.
- 지점 완료 시 완료 지점 수와 진행도가 갱신된다.
- 임무 종료 등급은 전체 실수 수, 복구 사용량, 지점별 연속 성공을 이용하되 현재 MVP의 1~3별 규칙과 호환한다.
- 중간 지점에서는 결과 화면으로 이동하지 않는다. 마지막 지점에서만 별·부품을 한 번 지급해 중복 보상을 막는다.

저장소에는 기존 `Progress` 형태를 유지하고, 임무 완료 순간에만 보상을 적용한다. 임무 중 새로고침이나 브라우저 종료는 미완료 보상을 저장하지 않는다.

## 4. 피드백과 오디오 구현 상태

`FeedbackBus`는 `input-correct`, `input-wrong`, `recovery-used`, `point-complete`, `mission-complete` 이벤트로 제한해 구현했다. UI는 색에만 의존하지 않고 아이콘·문구·상태 변화로 각 이벤트를 구분한다.

오디오는 짧은 Web Audio 신호를 사용하며, `Progress.settings.sound`가 false면 생성·재생하지 않는다. 오디오 초기화 실패는 게임 판정이나 시각 UI를 막지 않는다. 진동도 `Progress.settings.vibration`이 true인 경우에만 짧게 실행하고, 지원하지 않는 브라우저에서는 무시한다. 소리와 진동을 꺼도 임무 입력과 판정은 그대로 유지된다.

## 5. 꾸미기와 기지 성장 구현 범위

`Progress`에 현재 선택된 스킨과 해금 ID를 추가하고, 기존 저장 데이터는 기본값으로 안전하게 마이그레이션한다. 해금은 다음처럼 공개된 고정 조건을 사용한다.

- 기지 레벨 3: 헬멧 스킨 1
- 기지 레벨 5: 기지 장식 1

구조 부품 3개·6개에 따른 추가 꾸미기 해금은 후속 설계 아이디어로 남기며, 이번 구현 범위에는 포함하지 않는다.

선택 UI는 본부에서 열고, 잠긴 항목에는 조건을 표시한다. 서버·계정·결제·랜덤 보상은 추가하지 않는다.

본부의 `업데이트 내역` 버튼은 처음 닫힌 상태이며, `YYYY-MM-DD` 날짜와 제목·요약을 최신순으로 표시한다. 업데이트 기록은 정적 코드 목록으로 관리하고, 기능 변경마다 현재 날짜 항목을 목록 앞에 추가한다. 선택한 스킨과 장식은 브라우저 저장소에 유지한다.

## 6. 모바일과 접근성 기준

- 네 방향 버튼은 좁은 화면에서도 최소 64px 터치 영역을 유지한다.
- 버튼은 `aria-label`과 방향 아이콘을 함께 제공한다.
- 임무 화면은 세로 화면에서 패턴 카드, 진행도, 입력 패드 순으로 쌓인다.
- `blur`와 `visibilitychange` 모두 입력을 잠그고 일시정지 오버레이를 표시한다.
- 축소 모션에서는 장애물 이동·확대·흔들림을 정지 상태로 대체한다.
- 소리와 색을 끈 상태에서도 아이콘, 문구, 패턴 순서로 완료 가능해야 한다.

## 7. 검증 전략

단위 테스트는 수리 지점 전환, 마지막 지점 완료, 복구 한도, 보상 중복 방지를 검증한다. E2E는 튜토리얼 전체 완료, 중간·긴 임무 진입, 지점 진행도 증가, 마지막 결과·localStorage 저장을 검증한다.

최종 플레이테스트 매트릭스는 다음과 같다.

| 환경 | 확인 항목 |
| --- | --- |
| 데스크톱 키보드 | 방향키/WASD, 오입력 복구, 결과 저장 |
| 데스크톱 포인터 | 네 방향 버튼, 접근성 패널, 일시정지 |
| 좁은 터치 화면 | 버튼 크기, 세로 레이아웃, 패턴 가독성 |
| 소리·진동 끔 | 아이콘과 문구만으로 임무 완료 |
| 축소 모션 | 장애물과 전환 애니메이션이 정적 상태 |

구현된 브라우저 검증에는 `375x667` 본부 화면의 가로 넘침 여부, 축소 모션 설정에 따른 시작 버튼 강조 애니메이션 정지, 키보드 `Enter`로 업데이트 패널 열기를 포함한다. 실제 모바일 기기·브라우저 조합을 이용한 확장 매트릭스는 후속 검증으로 남긴다.

## 8. 비목표

이번 다음 단계에서는 멀티플레이, 계정 동기화, 서버 저장, 광고, 결제, 절차적 스테이지 편집기, 외부 분석을 추가하지 않는다.
