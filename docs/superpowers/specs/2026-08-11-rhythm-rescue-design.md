# 액션 퍼즐 게임 설계서: 《리듬 구조대》

작성일: 2026-08-11  
대상: 초등 5~6학년 중심의 1인 플레이어  
플랫폼: 키보드·마우스·터치를 모두 지원하는 웹 브라우저 게임

## 1. 게임 개요

《리듬 구조대》는 고장 난 로봇, 우주선, 우주 정거장에 출동해 수리 신호를 복원하는 구조 임무형 액션 퍼즐이다. 플레이어는 짧은 신호 패턴을 관찰하고 기억한 다음, 네 가지 방향 신호를 올바른 순서로 입력한다. 긴 임무에서는 이동 장애물, 시간 목표, 여러 수리 지점의 우선순위가 더해진다.

게임은 공부나 퀴즈처럼 보이지 않아야 한다. 핵심 감정은 “신호를 정확히 연결해 고장 난 기계를 다시 움직였다”는 구조의 성취감이다. 플레이 과정에서 작업 기억, 집중, 반응, 충동 조절과 관련된 행동을 자연스럽게 반복한다. 이 효과를 학습 성과나 지능 향상으로 단정해 홍보하지 않는다.

## 2. 목표와 비목표

### 목표

- 쉬는 시간에 3~15분 단위로 완결감 있는 임무를 제공한다.
- 키보드, 클릭, 터치에서 같은 난이도와 판정 경험을 제공한다.
- 실수해도 임무를 끝까지 완료할 수 있게 하되, 재도전할 이유를 남긴다.
- 콤보, 음악, 기지 확장, 꾸미기 보상으로 반복 플레이를 만든다.

### 비목표

- 실시간 대전, 협동, 채팅, 공개 순위표는 초기 버전에 넣지 않는다.
- 광고, 유료 확률형 보상, 연속 접속 보상, 자동 다음 임무 시작을 넣지 않는다.
- 폭력적 전투나 게임 오버 중심의 처벌 구조를 사용하지 않는다.

## 3. 핵심 플레이 루프

```text
구조 요청 선택
→ 수리 신호 관찰
→ 네 방향 신호를 순서대로 입력
→ 수리 결과·콤보·복구 신호 판정
→ 구조 부품과 별 획득
→ 기지 확장 또는 다음 구조 구역 해금
```

각 수리 지점은 `신호 표시 → 입력 대기 → 판정`의 짧은 단위로 구성한다. 신호는 색, 방향 아이콘, 짧은 애니메이션을 함께 사용한다. 소리는 보조 피드백이며, 소리를 끈 상태에서도 모든 정보를 파악할 수 있어야 한다.

### 입력 규칙

- 수리 신호는 위, 오른쪽, 아래, 왼쪽의 네 가지다.
- 키보드는 방향키와 WASD를 모두 지원한다.
- 마우스와 터치는 화면의 네 방향 큰 버튼을 누른다.
- 모든 입력은 `방향 신호`라는 같은 게임 액션으로 정규화한다.
- 중복 클릭, 길게 누르기, 같은 프레임의 복수 이벤트는 하나의 입력으로만 처리한다.

### 실패와 복구

- 잘못된 입력은 현재 콤보를 끊고 구조 시간 또는 등급에 작은 손해를 준다.
- 임무마다 두 번까지 복구 신호를 사용한다. 복구 신호는 틀린 지점부터의 짧은 패턴을 다시 보여 준다.
- 세 번째 실수 이후에도 임무는 계속하며, 해당 수리 지점의 보상 등급만 낮춘다.
- 실패 원인은 결과 화면에서 짧고 비난 없는 문장으로 설명한다.

## 4. 임무 길이와 난이도

| 임무 길이 | 내용 | 난이도 요소 |
| --- | --- | --- |
| 3~5분 | 수리 지점 약 3개, 패턴 길이 3~6 | 관찰·기억·입력의 기본 경험 |
| 7~10분 | 수리 지점 약 5개, 패턴 길이 5~9 | 느슨한 시간 목표와 방해 드론·가림 효과 |
| 10~15분 | 여러 장치를 복구해 우주선 또는 기지를 완성 | 수리 순서 선택, 긴 콤보, 복수 장애물 |

난이도는 한 임무에서 한 가지 변화만 추가한다. 예를 들어 패턴 길이를 늘린 임무에는 새 장애물을 함께 추가하지 않는다. 시간 제한은 즉시 실패 조건이 아니라 보상 등급 요소다.

## 5. 구조 구역과 성장

초기 구조 구역은 로봇 공장, 운송선, 궤도 정거장, 심우주선 순서로 해금한다. 각 구역은 고장 난 기계의 외형, 배경 음악, 장애물 표현만 달리하며 네 방향 수리 신호라는 핵심 규칙은 유지한다.

임무 보상은 별 1~3개와 구조 부품이다. 등급은 다음을 조합해 산정한다.

- 정확 구조: 잘못된 입력 수
- 연결 콤보: 연속 성공 수
- 신속 대응: 목표 시간 달성 여부
- 안전 수리: 복구 신호 사용량

구조 부품으로 기지를 `간이 차고 → 신호 관제실 → 드론 정비소 → 우주선 격납고 → 구조대 본부` 순으로 확장한다. 기지 확장은 새로운 구조 구역, 연습 시설, 로봇 색상, 헬멧, 신호 효과, 기지 장식을 해금한다. 모든 보상은 고정 조건을 공개하며, 무작위 상자나 유료 보상은 사용하지 않는다.

## 6. 화면과 접근성

임무 화면은 네 영역을 우선순위대로 배치한다.

1. 상단: 임무 이름, 콤보, 남은 시간 또는 목표 시간
2. 중앙: 수리 대상과 신호 패턴 표시
3. 보조 패널: 수리 진행도와 남은 복구 신호
4. 하단: 네 방향의 큰 입력 버튼과 입력 방식 안내

기본 접근성은 색 외의 방향 아이콘 병행, 큰 터치 영역, 음량과 진동 끄기, 화면 흔들림 줄이기, 시간 목표 완화 옵션이다. 브라우저 창이 비활성화되거나 포커스를 잃으면 임무는 자동 일시정지한다.

## 7. 권장 기술 구조

초기 구현은 TypeScript와 Phaser 기반의 단일 페이지 브라우저 게임을 권장한다. 백엔드·계정·온라인 통신은 요구하지 않는다.

| 구성 요소 | 책임 |
| --- | --- |
| InputAdapter | 키보드·클릭·터치 이벤트를 네 방향 게임 액션으로 변환 |
| MissionEngine | 표시, 입력, 복구, 완료 상태와 판정 관리 |
| PatternGenerator | 난이도 규칙에 맞는 패턴 생성 |
| ObstacleController | 난이도별 방해 요소의 표시와 상호작용 제어 |
| ProgressStore | 별, 구조 부품, 해금, 설정, 개인 기록의 로컬 저장 |
| Scene/UI | 본부, 임무 선택, 플레이, 결과 화면 표시 |

데이터 흐름은 `입력 장치 → InputAdapter → MissionEngine → 결과/보상 → ProgressStore → UI 갱신`이다. 저장소를 쓸 수 없는 환경에서는 경고를 표시하고, 해당 브라우저 세션 안에서만 진행한다. 오디오 재생이 실패해도 시각적 신호와 게임 진행에는 영향을 주지 않는다.

## 8. 검증 기준

- 패턴 생성기가 각 난이도의 길이와 변화 규칙을 지킨다.
- 세 입력 방식(키보드, 마우스, 터치)이 동일한 MissionEngine 상태 전환을 만든다.
- 복구 신호가 틀린 지점부터 패턴을 다시 보여 주고, 최대 두 번만 사용된다.
- 콤보, 별, 구조 부품, 기지 해금 계산이 일관된다.
- 저장·불러오기와 저장 불가 상황이 안전하게 처리된다.
- 키보드, 마우스, 터치 환경에서 튜토리얼부터 결과 화면까지 임무를 완료할 수 있다.
- 소리 없이, 색 인식만으로 의존하지 않고, 축소 모션 설정에서 플레이할 수 있다.

## 9. 초기 개발 범위

초기 버전은 하나의 튜토리얼 흐름, 세 가지 임무 길이, 네 방향 수리 신호, 복구 신호, 콤보와 별 보상, 기지 확장 화면, 로컬 저장, 기본 접근성 설정을 포함한다. 온라인 기능, 공개 경쟁, 결제, 새 입력 방식, 절차적 스테이지 생성은 이후 단계로 남긴다.
