# 《리듬 구조대》 3D 게임 재설계 문서

## 1. 목표

현재 Phaser 기반 2D 카드형 화면을, 학생이 수리 임무를 직접 수행하는 느낌을 받을 수 있는 3인칭 로우폴리 3D 브라우저 게임으로 재구성한다.

핵심 경험은 다음과 같다.

> 홀로그램으로 잠깐 본 패턴을 기억하고, 구조대원을 움직여 고장 난 로봇이나 우주선을 순서대로 수리한다.

기존 게임의 패턴 기억, 작업 기억 훈련, 집중력, 반응 속도, 충동 조절, 콤보, 보상, 기지 확장 규칙은 유지한다. 시각적 표현과 플레이 흐름은 Three.js 기반 3D 씬과 DOM HUD로 전환한다.

## 2. 승인된 방향

### 2.1 카메라

- 구조대원을 뒤에서 보는 3인칭 고정 추적 카메라를 사용한다.
- 자유 시점 회전은 첫 버전에서 제공하지 않는다.
- 카메라는 플레이어 이동을 부드럽게 따라가지만, 패턴과 수리 대상이 화면 중앙에서 읽히도록 시야를 유지한다.
- 메뉴·일시정지·접근성 패널이 열리면 게임 입력을 잠근다.

### 2.2 비주얼

- 장르 인상: 밝고 경쾌한 우주 구조대 애니메이션
- 모델 스타일: 장난감 같은 낮은 폴리곤 3D
- 팔레트:
  - 청록: 플레이어, 정상 신호
  - 라임: 정답, 콤보, 회복
  - 주황: 제한 시간, 경고
  - 분홍: 장애물, 오답
  - 금색: 보상, 기지 업그레이드
- 재질: `MeshStandardMaterial` 중심, 중요 오브젝트에만 약한 발광 재질 사용
- 조명: 환경광, 구조대원 림 라이트, 수리 대상 발광
- 배경: 짙은 남색 우주, 별가루, 네온 에너지 레일, 제한된 안개

### 2.3 플레이 루프

1. 기지에서 현재 기지 레벨과 보유 부품을 확인한다.
2. `출동 시작`을 눌러 구조 임무에 진입한다.
3. 수리 대상 주변 홀로그램 링에 표시된 짧은 패턴을 기억한다.
4. 패턴이 사라지면 키보드 방향키/WASD 또는 화면 버튼으로 순서대로 입력한다.
5. 정답 입력마다 구조대원이 해당 에너지 레일로 이동하고 전력 파동과 콤보가 발생한다.
6. 오답이면 장애물 효과가 발생하고, 남은 구조대 복구 횟수가 있으면 패턴을 다시 입력한다.
7. 모든 수리 지점을 완료하면 보상 등급에 따라 부품과 별을 받고 기지가 확장된다.

### 2.4 난이도

- 짧은 임무:
  - 패턴 기억과 빠른 입력 중심
  - 기본적으로 이동 장애물과 강제 제한 시간을 사용하지 않는다.
- 중간 임무:
  - 궤도를 도는 드론이 추가된다.
  - 수리 지점별 제한 시간이 추가된다.
  - 드론이 위험 레일을 가로지를 때 입력 타이밍을 주의해야 한다.
- 긴 임무:
  - 드론과 신호 차단막이 함께 움직인다.
  - 패턴 길이가 더 길고 제한 시간이 더 짧다.
  - 시각 효과는 강해지지만 패턴 표시 영역의 가독성을 침범하지 않는다.

## 3. 사용자 인터페이스

### 3.1 기본 HUD

게임 화면은 중앙 플레이필드를 보호하는 저밀도 HUD를 사용한다.

- 좌상단: 현재 목표와 수리 지점 진행률
- 우상단: 콤보, 최고 콤보, 부품 수
- 중앙 상단: 홀로그램 패턴 표시와 입력 진행률
- 하단 중앙: 네 방향 입력 버튼
- 하단 한쪽: 필요할 때만 나타나는 조작 안내 또는 위험 알림

상시 표시되는 정보는 짧은 라벨과 작은 미터로 표현하며, 긴 설명·스토리·전체 조작법·설정은 일시정지 또는 별도 패널에서만 보여준다.

### 3.2 단계 유도

다음 단계로 진행하려면 반드시 눌러야 하는 버튼에 `gi-pulse` 애니메이션을 적용한다.

- 기지의 `출동 시작`
- 첫 임무의 방향 입력 버튼
- 결과 화면의 `기지로 돌아가기`
- 다음 구조 요청으로 이동하는 버튼

버튼을 누르면 해당 애니메이션을 중지한다. reduced-motion 설정이나 운영체제 설정이 활성화되면 애니메이션 대신 정적인 강조 테두리를 사용한다.

### 3.3 반응형

- 데스크톱: 방향키/WASD와 넓은 4방향 버튼을 모두 제공한다.
- 모바일: 세로형 4방향 패드로 바꾸고 터치 영역을 52px 이상으로 유지한다.
- 작은 화면에서는 부가 상태를 한 줄 스트립으로 접고 패턴과 방향 버튼의 우선순위를 유지한다.
- 3D 장면의 중앙과 플레이어 주변에는 고정 패널을 놓지 않는다.

### 3.4 접근성

- 패턴, 정답/오답, 남은 복구 횟수, 임무 완료 메시지를 `aria-live` 영역에 전달한다.
- 색상만으로 상태를 구분하지 않고 아이콘, 문구, 모션 효과를 함께 사용한다.
- 설정 패널에서 소리, 진동, reduced-motion, 여유 있는 입력 타이밍을 조절한다.
- 메뉴가 열린 동안 게임 입력을 막고, 닫으면 마지막 게임 컨테이너로 포커스를 복귀한다.

## 4. 기술 아키텍처

### 4.1 런타임

- Three.js + TypeScript + Vite
- 직접 제어하는 `Scene`, `PerspectiveCamera`, `WebGLRenderer`, animation loop
- DOM 오버레이로 HUD, 메뉴, 설정, 업데이트 내역 구현
- 첫 버전은 고정 추적 카메라이므로 pointer lock을 사용하지 않는다.

### 4.2 모듈 경계

```text
src/
  core/                    패턴·콤보·복구·보상·진행 규칙
  game/
    simulation/            저장 가능한 임무·기지·타이머 상태
    input/                 키보드·터치 액션 매핑
    content/               임무별 연출과 수치 설정
  render/
    app/                   renderer·scene·camera·resize·loop
    objects/               구조대원·수리 대상·기지·장애물·레일
    materials/             재사용 머티리얼 팩토리
    assets/                안정적인 에셋 키와 GLTF 로더 경계
  ui/
    hud/                   목표·패턴·상태·방향 입력 UI
    menus/                 기지·일시정지·결과·업데이트 내역
  main.ts                 앱 진입점
  styles.css              게임 UI 토큰·레이아웃·모션
```

### 4.3 상태 소유권

- `src/core`와 `src/game/simulation`이 게임 규칙의 유일한 원천이다.
- Three.js 객체에는 점수, 콤보, 진행도, 저장 데이터를 기록하지 않는다.
- 렌더러는 시뮬레이션 상태를 받아 메시 위치·색상·애니메이션·파티클만 갱신한다.
- 저장소에는 직렬화 가능한 `Progress`만 저장하며, renderer나 WebGL 리소스는 저장하지 않는다.
- 타이머는 simulation이 소유하고 renderer와 HUD가 구독하는 방식으로 연결한다.

### 4.4 입력 액션

물리 입력을 게임 규칙에 직접 연결하지 않고 액션으로 변환한다.

```text
move-up     ArrowUp, W, 화면 위 버튼
move-right  ArrowRight, D, 화면 오른쪽 버튼
move-down   ArrowDown, S, 화면 아래 버튼
move-left   ArrowLeft, A, 화면 왼쪽 버튼
confirm     Enter, Space, 주요 버튼
pause       Escape, 일시정지 버튼
```

입력 어댑터는 현재 포커스가 게임 컨테이너에 있고 메뉴가 닫혀 있을 때만 방향 액션을 발행한다.

## 5. 3D 오브젝트와 에셋 정책

### 5.1 초기 오브젝트

- 구조대원: 헬멧, 몸통, 산소통, 도구 가방, 부츠를 기본 메시로 조합
- 수리 대상: 얼굴 디테일이 있는 소형 로봇과 모듈형 우주선 변형
- 기지: 착륙장, 통신 안테나, 부품 보관함, 업그레이드 모듈
- 에너지 레일: 방향별 발광 경로와 접점 링
- 장애물: 궤도 드론, 신호 차단막, 경고 링

### 5.2 에셋 포맷과 최적화

- 외부 모델을 추가할 때의 장기 런타임 계약은 GLB/glTF 2.0으로 고정한다.
- 현재 재설계 범위는 외부 파일 의존성을 줄이기 위해 procedural low-poly 메시 팩토리를 우선 사용한다.
- 오브젝트 식별자는 파일명 대신 `rescueAgent`, `repairRobot`, `signalDrone` 같은 manifest 키를 사용한다.
- GLB가 추가되면 `GLTFLoader` 경계에서만 로드하고, transforms·pivot·material reuse를 검증한다.
- 텍스처는 초기 버전에서 사용하지 않으며, 추후 사용 시 화면 점유도에 맞춰 WebP/AVIF 또는 KTX2/BasisU를 검토한다.
- 반복 오브젝트는 같은 geometry와 material을 재사용해 draw call과 메모리를 제한한다.

## 6. 모션과 피드백

- 카메라: 짧은 follow lerp와 수리 대상 중심 보정
- 구조대원: 입력 방향으로 짧은 이동·턴·도구 흔들기
- 정답: 라임 에너지 링, 짧은 파티클, 콤보 숫자 팝
- 오답: 분홍 스파크, 가장자리 경고, 장애물 통과
- 제한 시간: HUD 미터 색상 전환과 수리 대상의 점멸
- 임무 완료: 대상 점등, 부품이 기지로 날아가는 호밍 효과, 카메라 줌 아웃
- 모든 비필수 모션은 reduced-motion에서 축소하거나 정지한다.

## 7. 검증 계획

### 단위 테스트

- 기존 패턴 생성, 임무 엔진, 임무 진행, 보상, 저장소 테스트 유지
- 제한 시간의 시작·감소·만료 상태 테스트 추가
- 입력 액션의 키보드·터치 매핑 테스트 추가
- 기지 레벨과 코스메틱 해금 조건 테스트 유지

### 브라우저 테스트

Playwright로 다음 시나리오를 검증한다.

1. 기지 화면이 3D 캔버스와 DOM HUD를 함께 렌더링한다.
2. `출동 시작` 버튼이 보이고 `gi-pulse` 클래스를 가진다.
3. 첫 패턴 프리뷰가 표시된 뒤 입력 상태로 전환된다.
4. 방향 버튼과 키보드 입력이 같은 액션을 발행한다.
5. 정답 입력 시 콤보가 증가하고 오답 시 복구 상태가 표시된다.
6. 모든 수리 지점 완료 후 결과 화면이 열린다.
7. 기지 확장 보상이 저장된다.
8. `업데이트 내역` 버튼이 날짜별 기록을 열고 닫는다.
9. 모바일 뷰포트에서 방향 패드와 주요 버튼이 화면 밖으로 밀리지 않는다.

### 빌드·성능

- `npm test`
- `npm run build`
- `npm run test:e2e`
- WebGL renderer resize와 context loss 처리 확인
- pixel ratio를 최대 2로 제한
- 초기 장면에서 불필요한 post-processing과 과도한 UI를 사용하지 않음

## 8. 제외 범위

- 자유로운 3D 카메라 회전
- 온라인 멀티플레이
- 복잡한 물리 시뮬레이션
- 외부 CDN에 의존하는 필수 모델·텍스처·폰트
- 대규모 월드 탐색
- 첫 버전에서의 GLB 제작 도구 자동화

## 9. 완료 기준

다음 조건을 모두 충족하면 3D 재설계 작업을 완료한 것으로 본다.

- Phaser 화면이 제거되고 Three.js 렌더러가 기지·임무·결과 화면을 표시한다.
- 학생이 3D 구조대원과 수리 대상, 에너지 레일, 장애물을 한 화면에서 인지할 수 있다.
- 기존 패턴·콤보·복구·보상·기지 확장 규칙이 유지된다.
- 주요 다음 단계 버튼에 `gi-pulse`가 적용된다.
- 랜딩 화면에 작은 `업데이트 내역` 버튼과 날짜별 기록이 있다.
- 키보드와 터치 입력이 모두 동작한다.
- reduced-motion과 접근성 상태를 존중한다.
- 단위 테스트, 브라우저 테스트, 프로덕션 빌드가 통과한다.
- GitHub Pages 배포 URL에서 실제 게임 흐름을 확인할 수 있다.
