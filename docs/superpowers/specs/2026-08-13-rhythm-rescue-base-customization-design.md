# 리듬 구조대 기지 성장·꾸미기·업데이트 내역 설계

작성일: 2026-08-13
기준: 현재 `codex/mission-progression` 브랜치의 MVP

## 1. 목표와 범위

핵심 임무 루프와 피드백·오디오 구현 위에 반복 플레이 동기를 더한다. 플레이어가 임무를 완료해 구조 부품을 모으면 기지 레벨이 오르고, 고정 조건을 충족했을 때 스킨과 기지 장식을 해금·선택할 수 있어야 한다. 본부 화면에는 작은 `업데이트 내역` 버튼을 제공하고, 날짜별 변경 기록을 최신순으로 표시한다.

이번 사이클에 포함하는 범위는 다음과 같다.

- `Progress`에 선택 스킨, 선택 기지 장식, 해금된 꾸미기 ID를 추가한다.
- 기존 `localStorage` 저장 데이터가 새 필드 없이도 기본값으로 안전하게 읽히도록 마이그레이션한다.
- 기지 레벨 3에서 `rescue-helmet` 스킨, 레벨 5에서 `signal-hq` 기지 장식을 해금한다.
- 본부에서 해금 상태를 확인하고 해금된 항목을 선택할 수 있게 한다.
- 다음 단계 버튼인 `첫 구조 임무 시작`에 `gi-pulse` 애니메이션을 적용한다. 축소 모션 설정과 `prefers-reduced-motion`에서는 애니메이션을 끈다.
- 본부에 `업데이트 내역` 버튼과 접을 수 있는 날짜별 기록 패널을 추가한다.
- 진행도·마이그레이션·해금·선택·업데이트 패널·모바일 배치를 테스트한다.

포함하지 않는 범위:

- 결제, 계정, 서버 동기화, 무작위 보상
- 외부 이미지·음원 다운로드
- 임무 중 캐릭터 스프라이트를 교체하는 별도 렌더링 시스템
- 업데이트 기록을 런타임에서 Git에 쓰는 기능

## 2. 데이터 모델과 해금 규칙

기본 꾸미기 ID는 항상 해금된 상태로 둔다.

```ts
type CosmeticId = 'default-suit' | 'rescue-helmet' | 'signal-hq';

interface Progress {
  // existing fields
  selectedSkinId: 'default-suit' | 'rescue-helmet';
  selectedBaseDecorationId: 'default-hangar' | 'signal-hq';
  unlockedCosmeticIds: CosmeticId[];
}
```

해금 조건은 공개된 고정 규칙으로 유지한다.

| 조건 | ID | 종류 |
| --- | --- | --- |
| 기본 상태 | `default-suit` | 기본 스킨 |
| 기지 레벨 3 이상 | `rescue-helmet` | 헬멧 스킨 |
| 기지 레벨 5 이상 | `signal-hq` | 기지 장식 |

`applyMissionReward`는 보상 후 기지 레벨을 계산하고, 해당 레벨의 해금 ID를 누적한다. 이미 있는 ID는 중복 추가하지 않는다. 선택되지 않은 상태에서는 기본 ID를 유지하며, 저장 데이터에 선택 ID가 없거나 유효하지 않으면 기본 ID를 사용한다.

저장소는 기존 구조를 완전히 유효한 것으로 간주하지 않고, 읽은 객체를 `defaultProgress()`와 병합한 뒤 기존 값과 새 필드를 검증한다. 손상된 카운트·설정은 전체 기본값으로 되돌리되, 새 꾸미기 필드만 빠진 구버전 데이터는 기존 진행도와 설정을 보존한다.

## 3. 본부 UI와 상호작용

본부 화면은 현재 진행 통계와 임무 시작 버튼을 유지한다. 그 아래에 `기지 꾸미기` 섹션을 추가한다.

- 스킨 선택 버튼 2개: 기본 스킨, 헬멧 스킨
- 기지 장식 선택 버튼 2개: 기본 격납고, 신호 관제실
- 잠긴 항목은 `기지 레벨 3에서 해금` 또는 `기지 레벨 5에서 해금` 문구와 `disabled` 상태를 함께 표시한다.
- 선택된 항목에는 `aria-pressed="true"`와 시각적 선택 상태를 적용한다.
- 선택 변경은 즉시 `localStorage`에 저장하고 본부 화면의 테마 클래스를 갱신한다.

실제 게임플레이 규칙과 보상은 꾸미기 선택에 영향을 받지 않는다. 선택된 스킨은 본부의 구조대 카드 테마와 임무 HUD의 작은 배지로만 표현해 렌더링 시스템을 확장하지 않는다.

`업데이트 내역` 버튼은 본부의 보조 영역에 작게 배치한다.

- 최초에는 기록 패널을 닫는다.
- 버튼을 누르면 `details` 또는 동일한 접근성 동작을 가진 패널이 열리고 닫힌다.
- 기록은 `YYYY-MM-DD` 날짜, 제목, 변경 요약을 최신순으로 표시한다.
- 기록 데이터는 `src/core/update-history.ts`의 정적 목록으로 관리한다. 기능 변경 커밋마다 현재 날짜 항목을 목록 앞에 추가하는 규칙을 사용해 프로그램 변경 내용이 날짜별로 누적되도록 한다.

## 4. 모션과 반응형 규칙

`첫 구조 임무 시작`에는 `gi-pulse` 클래스를 붙여 다음 행동을 분명히 한다. `gi-pulse`는 색상 대비와 짧은 광택·확대 효과만 사용한다. 다른 보조 버튼에는 적용하지 않는다.

- `.reduced-motion` 또는 `prefers-reduced-motion: reduce`에서는 `animation: none`으로 정지한다.
- `375x667` 뷰포트에서 본부 카드가 화면 너비를 넘지 않아야 한다.
- 꾸미기 카드와 업데이트 패널은 세로로 쌓이며, 임무 시작 버튼과 접근성 설정 버튼을 가리지 않는다.
- 키보드 포커스 표시와 `aria-pressed`, `disabled` 상태를 유지한다.

## 5. 모듈 경계와 오류 처리

- `src/core/progression.ts`: 꾸미기 타입, 기본값, 해금 규칙, 보상 적용
- `src/storage/progress-store.ts`: 새 진행도 필드 검증·마이그레이션
- `src/core/update-history.ts`: 날짜별 업데이트 항목의 단일 원천
- `src/scenes/base-scene.ts`: 꾸미기 선택, 업데이트 패널, 저장 연결
- `src/styles.css`: 테마, `gi-pulse`, 모바일 레이아웃, reduced-motion

브라우저 저장이 차단되어도 현재 MVP와 동일하게 세션 UI는 동작해야 한다. 저장 실패는 진행 흐름을 막지 않는다. 허용되지 않은 꾸미기 ID나 잠긴 항목 선택은 상태를 변경하지 않는다.

## 6. 검증 기준

- 단위 테스트: 기본값, 레벨별 해금, 중복 방지, 구버전 저장 마이그레이션, 잘못된 꾸미기 선택 방어
- E2E: 본부에서 업데이트 패널 열기, 잠긴 항목 표시, 레벨 3·5 해금 상태, 선택 저장, `gi-pulse` 클래스, 모바일 폭
- 브라우저 플레이테스트: 본부 첫 화면, 꾸미기 선택, 업데이트 패널, 임무 시작 버튼과 설정 패널의 포커스·시각적 충돌
- 전체 검증: `tsc -b`, Vitest, Playwright, Vite build, `git diff --check`
